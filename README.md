# Практична робота №10

## Клієнтське програмування з бібліотеками та фреймворками (Vue/React)

### Формат

Комп'ютерний практикум

### Мета роботи

Обрати один із двох популярних клієнтських фреймворків - Vue 3 чи React 18 - і підключити його через CDN, без збірки й Node.js. Перенести список елементів варіанта, що дотепер рендерився вручну через DOM API (практикум 7), на компонентний підхід: окремий компонент отримує дані через props і рендерить їх декларативно, а одну інтерактивну дію реалізувати через подію фреймворку, яка автоматично оновлює реактивний стан і перемальовує інтерфейс - без ручного `querySelector` чи `innerHTML` для цієї ділянки.

### Варіант завдання

**Варіант 7 — Список бажань (Wishlist)**

- **Компонент:** `WishItem`.
- **Props:** `name`, `price`, `priority`.
- **Подія:** клік по чекбоксу «придбано» передає `toggle(id)` батьківському компоненту, який оновлює масив бажань.

### Обраний фреймворк

**Vue 3** (глобальна збірка з CDN). Шаблони пишуться прямо в HTML, не потрібен Babel для JSX, а реактивність дозволяє змінювати масив напряму - для невеликого застосунку це найпростіший варіант.

### Хід роботи

**Крок 1. Вибір фреймворку**
Обрано Vue 3. Обґрунтування вибору записано коментарем на початку `script.js` і в повідомленні коміту.

**Крок 2. Підключення CDN**
У `<head>` перед `script.js` підключено `https://unpkg.com/vue@3/dist/vue.global.js` з атрибутом `defer`, тож Vue завантажується раніше за код застосунку. Блок `<div class="layout">` отримав `id="app"` - на нього монтується застосунок Vue.

**Крок 3. Дані в реактивному стані**
Масив бажань перенесено з окремої змінної в `data()` кореневого компонента. Кожне бажання має поля `id`, `name`, `price`, `priority`, `bought` і за потреби `image`. Бажання з API JSONPlaceholder (практикум 9) після завантаження теж додаються в цей реактивний масив.

**Крок 4. Компонент WishItem**
Створено компонент `WishItem`, який отримує всі дані лише через props: `name`, `price`, `priority`, а також `id`, `image` і `bought`. Для props задано типи й значення за замовчуванням. Компонент не звертається до глобальних змінних.

**Крок 5. Рендер циклом**
Список виводиться директивою `v-for="wish in wishes"` з обов'язковим `:key="wish.id"`. Для кожного бажання створюється окремий екземпляр `<wish-item>`.

**Крок 6. Інтерактивна подія**
У картці є чекбокс «Придбано». Його зміна викликає `$emit('toggle', id)`. Батьківський компонент обробляє подію в методі `toggle(id)`: знаходить бажання за `id` і змінює поле `bought`. Vue сам перемальовує картку - вона стає напівпрозорою, а назва закресленою (клас `bought`).

**Крок 7. Прибирання ручного DOM-коду**
Функцію ручного рендеру `renderWishes` з практикуму 7 закоментовано в кінці `script.js` з поясненням, що її замінено компонентом `WishItem` і директивою `v-for`. Форма, кнопка «Оновити», статус завантаження й підсумкова сума також переведені на Vue (`@submit.prevent`, `v-model`, `@click`, `{{ }}`), тож `querySelector`, `createElement` та `innerHTML` у коді більше не використовуються.

**Крок 8. Перевірка автоматичного оновлення**
Зміна чекбокса «Придбано» миттєво змінює вигляд картки; додавання бажання через форму одразу показує нову картку й оновлює суму та кількість бажань. Жодного ручного оновлення DOM не потрібно.

**Крок 9. Перевірка у Vue DevTools**
У розширенні Vue.js devtools перевірено дерево компонентів: кореневий `App` і по одному `WishItem` на кожне бажання. У стані `App` видно масив `wishes` та обчислюване значення `total`, у кожного `WishItem` - його props. Під час кліку на чекбокс значення `bought` змінюється в DevTools.

**Крок 10. Коментар і збереження**
На початку `script.js` додано коментар про обраний фреймворк і причину вибору, зміни зафіксовано в Git.

```
git add .
git commit -m "Практична робота №10: список бажань на Vue 3 — компонент WishItem, v-for, подія toggle для «придбано». Vue обрано, бо шаблони пишуться прямо в HTML без Babel"
git push
```

### Компоненти

| Компонент | Що містить | Відповідальність |
|---|---|---|
| `App` (корінь) | `data`: `wishes`, поля форми, стан завантаження; `computed`: `total`; методи `toggle`, `addWish`, `validatePrice`, `loadData` | зберігає й змінює стан, завантажує дані з API |
| `WishItem` | props: `id`, `name`, `price`, `priority`, `image`, `bought`; подія `toggle` | відображає одну картку бажання й повідомляє про клік по чекбоксу |

### Приклад шаблону

```html
<wish-item
  v-for="wish in wishes"
  :key="wish.id"
  :id="wish.id"
  :name="wish.name"
  :price="wish.price"
  :priority="wish.priority"
  :bought="wish.bought"
  @toggle="toggle"
></wish-item>
```

```js
toggle(id) {
  const wish = this.wishes.find(w => w.id === id);
  wish.bought = !wish.bought; // Vue сам перемальовує картку
}
```

### Висновок

У результаті виконання практичної роботи список бажань переведено з ручного рендеру через DOM API на компонентний підхід із фреймворком Vue 3, підключеним через CDN без збірки. Дані зберігаються в реактивному стані `data()`, а кожне бажання відображає окремий компонент `WishItem`, що отримує дані лише через props і рендериться директивою `v-for` з унікальним `:key`. Клік по чекбоксу «Придбано» передає подію `toggle(id)` батьківському компоненту, який оновлює масив, після чого Vue автоматично перемальовує інтерфейс. Підсумкова сума реалізована як обчислюване значення `computed` і завжди відповідає поточним даним. Ручний DOM-код (`querySelector`, `createElement`, `innerHTML`) повністю замінено декларативними шаблонами. Дерево компонентів і стан перевірено у Vue DevTools.
